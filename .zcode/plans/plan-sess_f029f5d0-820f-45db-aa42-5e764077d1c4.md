## 目标
将 M4 DeFi 从「Agent 热钱包自动执行」扩展为「用户钱包签名 + Agent 广播」模式，同时保留原有热钱包模式作为可选项，由用户在 Agent 控制台切换。

## 用户已确认的关键决策
1. **执行模式**：用户钱包签名模式（Agent 组装 unsigned tx → 前端钱包 sign → 后端 broadcast raw tx）。
2. **模式切换**：Agent 级持久化设置（Profile 页开关）。
3. **签名入口**：聊天内直接签名（不全部进审批中心）。

## 方案概览

### 1. 持久化 Agent 级 swap 模式
- 新增 `agent_settings` 表：`token_id PRIMARY KEY`, `swap_mode TEXT CHECK('hot_wallet'|'user_wallet')`, `updated_at`。
- 后端新增 `core/settings.ts`：
  - `getSwapMode(tokenId)` / `setSwapMode(tokenId, mode)`
- 新增 API：
  - `GET /agents/:tokenId/settings`
  - `POST /agents/:tokenId/settings`（body `{ swapMode }`）
- 前端 Profile 页 Agent 控制台增加开关：「兑换执行模式：热钱包自动 / 我的钱包签名」。

### 2. 用户钱包模式下的 unsigned tx 组装
在 `agent/src/chain/defi.ts` 新增：
- `buildUnsignedNativeToTokenSwap(userAddress, amountInWei, amountOutMin, tokenOut)`
  - 原生币→代币：`to=router`, `data=swapExactAVAXForTokens/ETH`, `value=amountInWei`。
  - 收款地址为 `userAddress`（用户自己收 USDC）。
- `buildUnsignedTokenToNativeSwap(userAddress, tokenIn, amountIn, amountOutMin)`
  - 代币→原生币：`to=router`, `data=swapExactTokensForAVAX/ETH`。
- `buildUnsignedErc20Approve(userAddress, token, spender, amount)`
  - 用户授权 router / 路由使用其 USDC。
- `broadcastSignedTx(serializedSignedTx)`
  - 后端用 `publicClient.sendRawTransaction` 广播签名后的 raw tx。

函数名按链变体（AVAX/ETH）和当前 `executeSwap` 保持一致。

### 3. `propose_swap` 工具改造
`agent/src/skills/defi-swap/index.ts`：
- 输入增加可选 `executionMode?: 'hot_wallet' | 'user_wallet'`；未传时读取 `agent_settings`。
- `Proposal` 结构新增：
  - `executionMode`
  - `unsignedTxs?: UnsignedTx[]`
- **hot_wallet 模式**：保持现有逻辑（限额内自动执行 / 超限审批）。
- **user_wallet 模式**：
  - 组装 unsigned tx(s)，走同样的策略引擎限额/冷却/白名单。
  - 通过则返回 `verdict: 'sign'` + `unsignedTxs`，不执行。
  - 超限则返回 `verdict: 'rejected'` 或按金额策略提示用户切换模式。
  - 代币→原生币时：先查 allowance；不足则先返回一个 `erc20_approve` unsigned tx，approve 确认后再返回 swap unsigned tx（两轮到聊天签名）。

### 4. 聊天 Action 流程
- 扩展 `ChatResult`：增加可选 `action?: { type: 'sign_tx'; unsignedTxs: UnsignedTx[]; note?: string }`。
- 在 `runAgentTurn` 中识别 `propose_swap` 返回的 `verdict: 'sign'`，将 `unsignedTxs` 放入 `ChatResult.action`。
- 扩展所有 chat 端点响应：
  - `/agents/:tokenId/chat`
  - `/agents/by-owner/:address/chat`
  - `/conversations/:id/chat`
  均返回 `{ reply, refused, action? }`。
- 前端 `MyAgentPage`：
  - 收到 `action.type === 'sign_tx'` 时，在助手气泡下方渲染「🔏 签名并发送」按钮。
  - 点击后：
    1. `ensureTargetChain()`；
    2. 用 `walletClient.signTransaction(unsignedTx)` 逐笔签名；
    3. 把 serialized signed txs POST 到后端广播端点；
    4. 显示 txHash / 错误。

### 5. 广播端点
新增 `POST /agents/:tokenId/broadcast`（或 `/tx/broadcast`）：
- body: `{ signedTxs: string[] }`
- 后端按顺序 `sendRawTransaction`，对于 approve + swap 这种依赖关系等待前一笔确认后再广播下一笔。
- 每笔成功后写入 `tasks` 表作为审计记录。
- 返回 `{ txHashes: string[], explorer: string }`。

### 6. 边界与兜底
- Gas：用户钱包模式由用户支付 gas；Agent 不再配置 `value` 以外的 gas 参数，交给钱包估算。
- 模式默认：`hot_wallet`，避免破坏现有行为。
- 审批中心：保留给热钱包模式的超限场景；用户钱包模式下超限直接拒绝并提示切换模式或降低金额。
- 错误处理：广播失败（revert / 余额不足 / 网络）返回具体错误，前端 toast 提示。

## 待确认点
1. 代币→原生币的两步签名（approve + swap）是否接受“先签 approve，后端确认后再签 swap”的两次聊天交互？还是你更希望在审批中心里一次性展示两步？
2. 用户钱包模式下的小额自动执行是否仍需要策略引擎限额？（当前计划保留：超限额直接拒绝。）
3. `swapMode` 默认值：保持 `hot_wallet` 还是改为 `user_wallet`？

1. TypeScript `tsc --noEmit` 通过。
2. 后端单元/手动测试：
   - 切换 swapMode 为 user_wallet；
   - 发送「0.02 AVAX 换 USDC」得到 unsigned tx；
   - 前端签名后后端广播成功并返回 txHash。
3. 热钱包模式回归：切回 hot_wallet，限额内仍能自动执行。
